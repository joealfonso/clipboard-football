## 1. Franchise core and franchise screens

### Resolved: the five approved additions

The lead already sent these to the engineer building core milestones A and B. The core spec should gain this text.

Under "Draft (B)", new bullets:

> - **Targets.** The user can mark any undrafted pool player as a target and unmark him. `setTarget(state, playerId, on)` returns a typed error for an unknown or already drafted player and leaves the state unchanged. Targets are a list of player ids in the franchise state, in the order marked. A target who is drafted stays in the list, so the screen can say which targets were taken. Views filter to the targets still available. AI teams never read the list.
> - **Use.** For the user's team, each available player carries `use`: `starter` when the team's count at his position is under `min`, `depth` when it is at least `min` and under `target`, `extra` when it is at `target` or more. He also carries `depthRank`, the place he would take in the team's depth order (overall descending, ties by id).
> - **Must fill.** `mustFill` is the list of positions and counts the user's team still has to draft when its picks left equal the sum of `neededToStart`. Otherwise it is empty.
> - **Auto-pick preview.** `autoPickPreview(state, data)` returns the player auto-pick would take now and one reason code with its numbers, from the factors the pick used and nothing else: `target` (a saved target was taken), `need` (the need bonus was above zero: position, count, min, target), `value` (the need bonus was zero). Null when the user is not on the clock or has no legal pick.

Replace the "User" bullet's rule for auto-pick with:

> Auto-pick and auto-draft take the user's highest-overall target (ties by id) that is legal and whose `use` is `starter` or `depth`. With no such target they pick by the AI policy.

Add to the "Draft view" bullet:

> Also: `totalPicks`, `done`, `userPicksMade`, `userPicksTotal`, `userNextPick` (overall pick, round, pick in round and picks away, for the user's next slot after the current pick, null when there is none), `targets`, `mustFill` and `autoPickPreview`. `picksForSlot(slot, data)` returns the overall pick numbers a slot owns and works before a franchise exists.

Criteria:

> - B6, reworded: with no usable target, auto-pick equals what the AI policy would pick for that team. With one, it takes the highest-overall usable target. Auto-draft follows the same rule.
> - B11, new: targets round-trip through JSON mid-draft, and every AI team's picks are identical with and without user targets when the user's own picks are the same.
> - B12, new: over 200 seeded states, `autoPickPreview` names the player auto-pick then drafts, and its reason code matches the branch taken.

Under "State, save and worker API (H)", the Draft line gains "the user's targets". That makes targets part of the save schema Joseph signs off (Decisions for Joseph, 1).
